# task_scheduler
Задачі-нагадування: SCHEDULED → DUE → SEEN → DONE. Тік 1 с, час у UTC.
Чистий C, без ESP-IDF. Власник: B. Завдання B6.

## API
`ts_init`, `ts_set_schedule` (розклад від бота), `ts_restore` (відновлення з NVS),
`ts_handle_event` (кнопки «бачу» / «виконано»), `ts_tick` (раз на секунду),
`ts_schedule`, `ts_schedule_version`, `ts_find`, `ts_active`, `ts_due_count`,
`ts_local_minute_of_day`, `ts_status_name`. Повний опис — у `task_scheduler.h`.

## Як користуватися (Logic Task)
```c
static task_scheduler_t s_ts;               // ~1,4 КБ: static, не на стеку
ts_init(&s_ts, &cfg);

// раз на секунду; now_utc < 0, якщо SNTP ще немає
if (ts_tick(&s_ts, 1, now_utc, esp_timer_get_time(), &out)) { /* EVT_TASK_DUE */ }

// на кожну вхідну подію EVT_TASK_SEEN / EVT_TASK_DONE
if (ts_handle_event(&s_ts, &in, &out)) { /* підтверджена зміна статусу */ }

// розклад від MQTT (C/D): прийме лише НОВУ версію
fd_err_t e = ts_set_schedule(&s_ts, &sched, now_us, &out);   // FD_OK → EVT_SCHEDULE_UPDATED
```

## Правила
- **Повтор нагадування** кожні `task_repeat_s` (60 с) до «бачу»; після «бачу» повторів немає.
  Подія EVT_TASK_DUE має `value` = номер нагадування (0 — перше, 1, 2 … — повтори).
- **Затримка нагадування** — не більше одного тіку (1 с) після `time_utc` (вимога E4: ≤ 5 с).
- **Одна подія за тік.** Якщо кілька задач настали одночасно, решта отримає подію
  на наступних тіках (порядок: нова DUE → відновлена після перезапуску DUE → повтор).
- **Кнопка без id** (`id == 0`): «бачу» діє на першу DUE-задачу; «виконано» — на першу
  SEEN, а якщо таких немає, на першу DUE. З `id` (від бота, `/done <id>`) можна закрити
  будь-яку незакриту задачу, навіть SCHEDULED.
- **Розклад.** Приймається лише `schedule_version` більша за поточну; дубль або старішу
  відхиляє `FD_ERR_STATE` (sync при цьому варто все одно підтвердити ack, щоб бот не
  повторював). Статус задач з тим самим `id` і часом зберігається; якщо час змінили, задача
  знову SCHEDULED (крім DONE: закрита лишається закритою). `id == 0` і дублі `id`
  відхиляються (`FD_ERR_INVALID_ARG`).
- **Пропущений час.** Задача, час якої вже минув на момент прийому розкладу, стає DUE
  на найближчому тіку (E5: втрачених нагадувань має бути 0).
- **Час невідомий** (`now_utc < 0`): нові задачі не спрацьовують, але вже DUE повторюють нагадування.
- **Відновлення після перезапуску** (`ts_restore`, B8): DUE-задачі отримують нагадування
  на найближчому тіку; SEEN і DONE мовчать (E6).

## Відкрите питання до команди
У таблиці 7.4 методички повтор нагадування записано в рядку SEEN, а в таблиці 7.5 —
«кожні 60 с **до «бачу»**». Реалізовано друге (повтор лише в DUE). Якщо потрібно, щоб
SEEN-задача теж нагадувала, це зміна в `ts_tick` (одне правило).
